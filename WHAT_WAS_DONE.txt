1. OVERVIEW & OBJECTIVE ACCOMPLISHED
--------------------------------------------------------------------------------
Built a complete, high-fidelity, browser-based hardware simulator for CHĀTURANGA,
an AI-powered electronic chessboard project. The simulator models an 8x8 physical
chessboard with 64 reed switch occupancy sensors, a virtual ESP32-WROOM-32
microcontroller, square LED outputs, an SSD1306 monochrome OLED display, and a
clean API service layer supporting both Mock Backend and Live Flask Backend modes.

3. DETAILED IMPLEMENTATION OF REQUIRED FEATURES
--------------------------------------------------------------------------------
1. Interactive 8x8 Chessboard:
   - Complete standard starting position with coordinates (a-h, 1-8).
   - High-contrast board squares with wood/slate aesthetics and coordinate tags.

2. Drag-and-Drop & Click-to-Move:
   - Smooth HTML5 and pointer drag & drop with grab/grabbing feedback.
   - Decoupled physical reed sensor triggers (lifting a piece sets square to 0,
     placing a piece sets square to 1).

3. Sensor-Debug Override Mode:
   - Dedicated toggle switch allowing any of the 64 squares to be toggled
     between 0 and 1 independently of piece presence.
   - Allows simulating hardware faults (stuck reed switches, missing magnets).

4. 64 Sensor States & Occupancy Bitmap:
   - Visual badges on all 64 squares indicating occupancy (1 = green, 0 = dark).
   - Real-time 64-bit Hex display (Starting position: 0xFFFF00000000FFFF).
   - Interactive 8x8 binary matrix grid (ranks 1 to 8).
   - Square mapping: a1 = bit 0 (LSB) ... h8 = bit 63 (MSB).

5. Virtual ESP32 Microcontroller Simulation:
   - Configurable scan frequency (20ms to 1000ms slider, default 100ms).
   - N-cycle debounce filter (1 to 10 cycles slider, default 3 cycles).
   - Hardware SMD LEDs: PWR (Red), WIFI (Green), TX (Cyan flash), RX (Yellow flash).
   - State machine: BOOT -> IDLE -> DEBOUNCING -> STABLE -> TRANSMITTING -> RETRY/ERROR.
   - Exponential backoff retry logic upon transmission failure.

6. Virtual Square LEDs:
   - 4 corner micro-LEDs plus square underglow on all 64 squares.
   - Supports GREEN, CYAN, RED, YELLOW, WHITE with SOLID, PULSE, and FLASH animations.
   - Visual feedback for move confirmation, legal target suggestions, and illegal move alerts.

7. Virtual SSD1306 128x64 OLED Display:
   - HTML5 Canvas rendered at 256x128 with pixel-crisp retro styling and phosphor scanlines.
   - Displays Wi-Fi status, system mode ([MOCK]/[FLASK]), active player turn,
     last move, sensor count, and alert banners.

8. Separated Loggers & Network Inspector:
   - Sensor Events Log: Physical hardware telemetry and debounced transitions.
   - Move History Log: Validated official chess moves with SAN, UCI, and check flags.
   - Network Inspector: Live REST HTTP transaction cards (method, endpoint, status,
     latency, request payload, response payload).
   - FEN History Panel: Chronological list of authoritative FEN strings with copy button.

9. Simulation Controls:
   - Pause / Resume scan loop button.
   - Reset Board & ESP32 button.
   - Clear Logs button.
   - Test Move Rejection button (injects illegal move to test error flow).

10. Mock Mode & API Service Layer:
    - ApiService module with clean methods (`sendHardwareScan`, `getGameState`, `resetGame`).
    - Toggle between MOCK mode and Live Flask Backend (http://localhost:5000).
    - MockBackend implements standard chess rules, turn order, legal move checks,
      and authoritative FEN generation matching python-chess.

11. Network Loss & Move Rejection Simulation:
    - "Simulate Lost Network Connection" toggle forces HTTP timeouts.
    - ESP32 enters RETRY mode with OLED notification and retry counter.
    - Illegal moves return status 'rejected', triggering flashing red LEDs and OLED warnings.

12. Responsive Design & Offline Capability:
    - 100% self-contained: works with zero external CDN dependencies.
    - Dark laboratory glassmorphic UI with CSS grid and responsive breakpoints.
